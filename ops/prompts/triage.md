# triage — 初期実装はキーワードルール (LLM なし)

フィードバックの一次分類 (veto / stop_all / review_needed) は `ops/heart/triage.py` の
決定論ルールで行う。モデルを使わない理由:

- **停止・拒否の意思は誤分類が許されない。** 「止めて」がモデルの解釈を経由すると、
  解釈の失敗がそのまま人間のコントロール喪失になる。キーワード一致は貧弱だが確実
- 弱いモデルにエスカレーション判断をさせると「助けを呼ぶべき時」を認識できない
  (2025-26 の実運用知見。強いモデルでも未解決)

分類できないものは全て `review_needed` に落ち、daily briefing に載って人間と
consolidation の目に入る。**取りこぼしは「無視」ではなく「翌日回し」に倒れる。**

## 将来 LLM 化する場合の条件 (models.json の triage を変える前に)

1. veto / stop キーワードの決定論パスは **残す** (LLM は review_needed の細分類のみ)
2. 分類の出力は enum 選択のみ (自由記述の解釈をさせない)
3. parse 失敗時の既定値は保守側 (review_needed)
